## Phase E — OPEN, in progress 2026-08-25: full ECO A00-E99 cross-check against chessopenings.com

**Started this session, after the c4_openings A11-A39 work (see the c4_openings batch entries below) surfaced [chessopenings.com/eco/&lt;CODE&gt;](https://chessopenings.com/eco/) as a fast, reliable, static index of every ECO code's named sub-variations + exact PGN.** The user asked for a full repo-wide sweep using it as the discovery source. **`ECO/eco.md`, already committed to the repo, is the permanent artifact of that discovery pass — all 500 codes (A00-E99), 2013 named sub-variation entries, already scraped and saved.** A fresh session does **not** need to re-fetch chessopenings.com at all; just read `ECO/eco.md`.

**The method, exactly as the user specified it — apply this per code, front-by-front, in batches of ~10 codes at a time (A00-A09, A10-A19, ... through E90-E99, ~50 batches total):**

1. For each ECO code in the batch, check `ECO/eco.md`'s entries for it against the repo's own existing cards.
2. **If no card exists at all for that code's root** — that's the highest-priority gap; give it one, same style/rigor as every other card in this repo (live Lichess verification for every stat/eval, never trust chessopenings.com's own numbers, only its move sequences/names).
3. **If a card exists**, check each of that code's named sub-lines from `eco.md`:
   - If the sub-line sits within the card's own depth budget (3 plies past the card's title position for a "main" card; deeper is fine for a trap/gambit/pattern card per `start.md`'s existing exemption) **and isn't already covered** — add it in properly: diagram, FEN, live Stockfish eval (via `tools/explore.py`/cloud-eval, or the `scratchpad/eco_crawl.py` masters-lookup helper — see below), matching the card's existing NOTE style.
   - If the sub-line is genuinely too deep for that card's own budget — add only a brief `[!NOTE]` mention (name + move sequence, one live-verified eval, no full diagram/stats treatment) so the name is at least discoverable, matching the precedent set on `Amar.md` (Amar Gambit) and `Vant_Kruijs.md` (Amsterdam Attack) this session.
4. **After treating a code's entries, mark them in `ECO/eco.md` itself** — append `` ✅ [covered](<github blob URL to the card>#<anchor if any>) `` to the end of that entry's line, so the reference doc doubles as a running checklist. An entry with no trailing `✅` is not yet checked/treated. (The annotation script used this session lives at `scratchpad/build_gap_report.py`'s sibling — not promoted to `tools/`, since scratchpad doesn't survive a session; the next session should just hand-edit `eco.md` lines directly, appending the same `✅ [covered](url)` suffix format, rather than rebuild the script from scratch unless doing a big batch at once.)
5. **Watch for the "wrong root code" bug class** while doing this (see the four already-found instances below) — a card's own root or main-line position can carry a *different* ECO code than the card's title claims. Always spot-check the card's own root FEN against `tools/explore.py`'s live `opening` field, not just against what `eco.md` implies (the two should agree, but only the live explorer is authoritative for this repo's own claims).
6. **Every number that ends up in a card (eval, masters game count, popularity %) must be independently live-verified via the Lichess explorer/cloud-eval — chessopenings.com is a discovery/naming source only, never a stats source.** Sanity-check every hand-typed FEN's eval for plausibility before trusting it (this session hit the same "forgot an already-present pawn" FEN bug twice more while doing this — see the c4_openings batch notes below; it's a recurring failure mode, not a one-off).

## File naming convention (established 2026-08-25, repo-wide cleanup)

Card filenames are `<ECO or folder prefix>_<Name>[_<disambiguator>].md`. A move fragment (like `Nf3`, `d4`, `1e4d5`, `exd5`) belongs in the filename **only** when it's the actual thing distinguishing this card from a sibling that would otherwise share the same name — never just because it's part of the position's move sequence.

- **Drop the move** when the ECO code + descriptive name already uniquely identify the card on their own — e.g. `B01_1e4d5_Scandinavian.md` → `B01_Scandinavian.md` (no other B01 file is called Scandinavian, so the move added nothing). This was the common case: 22 files repo-wide had a redundant move fragment as of the 2026-08-25 cleanup.
- **Keep the move** when siblings share a generic name and the move is the real differentiator — e.g. `B30_Sicilian_Nc6_Open.md` / `B34_Sicilian_g6_Accelerated_Dragon.md` / `B40_Sicilian_e6_Open.md` / `B50_Sicilian_d6_Open.md` all say "Sicilian ... Open" and only the move tells them apart. Same logic kept `C88_Ruy_Lopez_Closed_Bb3.md` (no proper name exists for that specific 7. Bb3 branch) and `D02_QPG`'s move-free rename to `D02_Zukertort_Variation.md` was possible *because* a real name existed — contrast with keeping `C44_Nc6_King_Knight.md`'s "Nc6" since it only differs from sibling `C40_King_Knight.md` by that one move, not by name.
- Repeating the same descriptive name across different ECO codes without any move at all is fine and already the norm — e.g. `B02_Alekhine_Defense.md`/`B03_Alekhine_Defense.md`, `B07_Pirc_Defense.md`/`B08_Pirc_Classical_System.md`, the whole `Ruy_Lopez` family. The ECO prefix alone is enough to keep filenames unique; don't add a move just because two files share a name.
- Three files were missing their ECO prefix entirely (`e4_Nc6_Nimzovitch.md`, `e4_c6_Caro_Kann.md`, `e4_e6_French.md`) — found by reading each file's own title line, which always states the real ECO. Renamed to `B00_Nimzowitsch_Defense.md`, `B10_Caro_Kann.md`, `C00_French_Defense.md` respectively (also fixed the "Nimzovitch" → "Nimzowitsch" spelling to match the title's own usage).
- **How the rename was done safely**: `git mv` for each file (preserves history as a rename, not delete+add), then a repo-wide script replacing every literal occurrence of each old filename with its new one (link text stays untouched — only the filename portion inside `.../blob/main/...` URLs changes), then three independent verification passes: `tools/check_diagram.py` (validates every Mermaid `click` target resolves, whole repo), a grep-based scan confirming zero remaining references to any old filename anywhere in the tree, and a full audit of every `github.com/.../blob/main/...` link in every `.md` file resolving to a real path on disk. All three came back clean. This three-pass pattern is worth reusing for any future bulk rename — `check_diagram.py` alone only covers the 59 files that have a Mermaid diagram, not every prose link.

## Environment prerequisites (local dev machine)

Two local blockers, diagnosed 2026-08-23, needed before any live Lichess query works from this machine's MSYS2/mingw64 Python (`C:\msys\mingw64\bin\python.exe`, no pip, no bundled CA store):

1. **CA bundle**: `SSL_CERT_FILE` → `C:\Users\march\.certs\cacert.pem` (fetched from `https://curl.se/ca/cacert.pem`). Without it, `urllib` fails with `CERTIFICATE_VERIFY_FAILED` (curl itself is unaffected — it uses a different trust store).
2. **Lichess token**: anonymous explorer requests are refused (HTTP 401) from this network. `LICHESS_TOKEN` (no scope needed) must be set — the same token already used by the `update-stats.yml` GitHub Actions secret works fine locally too.

Both are persisted as **Windows user environment variables** (`setx` / `[Environment]::SetEnvironmentVariable(..., "User")`), so any *new* shell (PowerShell or Git Bash) picks them up automatically. A shell that was already running before they were set will not see them — export inline for the rest of that session:

```
SSL_CERT_FILE=/c/Users/march/.certs/cacert.pem LICHESS_TOKEN=<token> python tools/update_stats.py ...
```

**Stockfish evals**: no local engine is installed. Use the Lichess cloud-eval API instead (same token, same trust store):
```
curl -H "Authorization: Bearer $LICHESS_TOKEN" "https://lichess.org/api/cloud-eval?fen=<url-encoded FEN>"
```
Returns `{"cp": N}` or `{"mate": N}`. Sign convention verified against A00's documented "#-1" line: **positive = good for White**, same as the notation already used throughout the repo (`+0.x` / `-0.x` / `#-N`). Convert `cp` → pawns by dividing by 100. Not every obscure sideline is cached server-side — if cloud-eval 404s, don't invent a number; fall back to prose.
