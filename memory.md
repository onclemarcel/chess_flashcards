## Environment prerequisites (local dev machine)

Two local blockers, diagnosed 2026-08-23, needed before any live Lichess query works from this machine's MSYS2/mingw64 Python (`C:\msys\mingw64\bin\python.exe`, no pip, no bundled CA store):

1. **CA bundle**: `SSL_CERT_FILE` → `C:\Users\march\.certs\cacert.pem` (fetched from `https://curl.se/ca/cacert.pem`). Without it, `urllib` fails with `CERTIFICATE_VERIFY_FAILED` (curl itself is unaffected — it uses a different trust store).
2. **Lichess token**: anonymous explorer requests are refused (HTTP 401) from this network. `LICHESS_TOKEN` (no scope needed) must be set — the same token already used by the `update-stats.yml` GitHub Actions secret works fine locally too.

Both are persisted as **Windows user environment variables** (`setx` / `[Environment]::SetEnvironmentVariable(..., "User")`), so any *new* shell (PowerShell or Git Bash) picks them up automatically. A shell that was already running before they were set will not see them — export inline for the rest of that session:

```
SSL_CERT_FILE=/c/Users/march/.certs/cacert.pem LICHESS_TOKEN=<token> python tools/update_stats.py ...
```

**Stockfish evals**: no local engine is installed. Use the Lichess cloud-eval API instead (same token, same trust store):
```
curl -H "Authorization: Bearer $LICHESS_TOKEN" "https://lichess.org/api/cloud-eval?fen=<url-encoded FEN>"
```
Returns `{"cp": N}` or `{"mate": N}`. Sign convention verified against A00's documented "#-1" line: **positive = good for White**, same as the notation already used throughout the repo (`+0.x` / `-0.x` / `#-N`). Convert `cp` → pawns by dividing by 100. Not every obscure sideline is cached server-side — if cloud-eval 404s, don't invent a number; fall back to prose.
